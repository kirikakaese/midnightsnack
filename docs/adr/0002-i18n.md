# 0002. Internationalization

- **Status:** accepted
- **Date:** 2026-10-08

## Context

Only English ships at launch, but community translations must be trivial. Translators need
plurals and placeholders. User-facing text appears in the frontend and, occasionally, in errors
that originate in Rust.

## Decision

- All user-facing strings live in flat JSON catalogs in `packages/ui/src/locales/<locale>.json`
  using **ICU MessageFormat** syntax.
- A small runes-based wrapper around `intl-messageformat` (`packages/ui/src/i18n`) provides
  `t(key, values)` with a reactive locale and English fallback. We chose this over `svelte-i18n`
  to stay compatible with Svelte 5 runes and avoid a bundled CLI toolchain.
- `t()` keys are typed from `en.json`, so a typo is a type error.
- Rust never produces user-facing prose: it reports stable `ErrorCode`s (in `crates/protocol`)
  that the frontend translates (`error.<code>` keys).
- `pnpm i18n:check` validates catalogs in CI.

## Consequences

- Adding a language is a single JSON file plus registering it in the i18n module.
- Native OS surfaces (menus, tray, dialogs titles) need strings passed from the frontend or a
  later Rust-side catalog; revisit if that grows.
