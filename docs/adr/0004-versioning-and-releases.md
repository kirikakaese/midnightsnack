# 0004. Versioning and release scheme

- **Status:** accepted
- **Date:** 2026-10-08

## Context

Each roadmap phase ends with a tagged pre-release. Windows MSI (WiX) only accepts numeric
versions, so SemVer pre-release suffixes such as `-alpha.1` break MSI builds.

## Decision

- Phase *N* (1–6) is released as `v0.N.0`; phase 0 as `v0.0.1`; follow-up fixes as patch
  versions. Phase 7 produces `v1.0.0`.
- All `v0.*` releases are published as GitHub **pre-releases**.
- Pushing a `vX.Y.Z` tag runs `.github/workflows/release.yml`, which builds the installers,
  creates a draft release with a changelog generated by git-cliff from Conventional Commits,
  and uploads `SHA256SUMS.txt`.
- The version lives in the root `Cargo.toml` (`workspace.package.version`) and in
  `apps/host/src-tauri/tauri.conf.json` (taken from Cargo when absent).

## Consequences

- No `-alpha`/`-beta` tags; "pre-release" is expressed via GitHub's flag and the `0.x` major.
- Code signing, notarization and auto-update are out of scope for now (unsigned-app warnings are
  documented for users).
